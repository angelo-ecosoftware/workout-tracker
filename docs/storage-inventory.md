# Browser storage inventory

This document records the browser storage currently used by Kinisia. Supabase remains
the source of truth for user, routine, workout, exercise, session, and progress data.

## `localStorage`

### User-scoped data

These keys must include the authenticated user ID:

- `user_metrics_<userId>` — cached profile metrics used by the header.
- `body_logs_<userId>` — cached body-weight log fallback.
- `saved_programs_<userId>` — cached saved routine library fallback.
- `onboarding_profile_<userId>` — onboarding draft.
- `onboarding_deferred_<userId>` — onboarding deferral state.
- `welcome_shown_<userId>` — welcome modal dismissal.
- `selected_workout_<userId>` — selected workout continuity.
- `workout_expanded_ex_<userId>_<workoutId>` — expanded exercise continuity.
- `workout_session_active_<workoutId>` — active workout marker.
- `workout_session_start_time_<workoutId>` — active workout start timestamp.
- workout draft keys generated by `getWorkoutDraftKey(...)`.
- draft photo keys generated by the draft photo storage utility.

### Global preferences

These keys intentionally apply to the current browser profile:

- `workout_tracker_active_tab` — last application section.
- `coach_personal_workout_mode` — coach workspace mode.
- `setting_rest_duration_seconds` — rest timer preference.
- `setting_sequential_set_mode` — sequential set preference.
- `setting_assisted_timed_workout` — timed-workout preference.
- `workout_recovery_expanded` — recovery card expansion.
- `theme` — application theme.
- `custom_exercise_gif_<exerciseId>` — exercise media override.
- `exercise_catalog_cache` — cached exercise catalog.
- `food_catalog_<userId>` and `hive_mind_food_catalog_cache` — food catalog caches.
- `diet_log_<userId>_<date>` — dietary fallback cache.

### Security and protection state

- bot-defense fingerprint and ban keys.
- account deletion clears application local storage.

## `sessionStorage`

Session-only values currently include:

- route continuity and scroll position.
- bot-defense temporary ban state.

## Rules for future changes

1. Server-owned data must not rely on local storage as its only copy.
2. User data must include a user identifier in the key.
3. Every JSON value needs malformed-data fallback behavior.
4. Large or frequently changing data should use IndexedDB or the server instead.
5. New keys must be added to this inventory and covered by a focused test.
6. Account deletion must remove every user-owned browser-storage key.
